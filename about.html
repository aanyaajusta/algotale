About this project

This project was made for the prompt engineering course. The main topic is prompt engineering. The second topic is data structures and algorithms, and we chose binary search.

The site is static, which means plain HTML, CSS, and JavaScript with no server. It is hosted for free on GitHub Pages.

What we did

  • Wrote a basic prompt and a structured prompt for the same problem.
  • Compared the AI replies to each prompt.
  • Tested the returned code with five test cases.

Prompt engineering patterns

A prompt pattern is a reusable way of structuring a request to a language model. Patterns are not rules that always work. They are starting points you can adapt and test. The five patterns below are the ones we studied and used in the Prompt Lab.

1. Persona pattern

The persona pattern asks the model to act as a specific role, such as a teacher, an interviewer, or a code reviewer. The role shapes the knowledge the model draws on and the tone it uses.

Example: "You are a DSA tutor for second-year students."
In our project: the Role field in the Prompt Lab.

2. Audience persona pattern

This pattern tells the model who the answer is for. The same question needs a different explanation for a beginner than for an experienced developer. Describing the reader's background helps the model choose the right depth and vocabulary.

Example: "Explain binary search to someone who knows loops but has not studied sorting algorithms."
In our project: we used a second-year student as the audience when checking whether the explanation was clear enough.

3. Question refinement pattern

With this pattern, you ask the model to improve your question before it answers. Vague questions get vague answers. Asking the model to point out missing details or suggest a sharper version often produces a better final prompt.

Example: "Before answering, suggest a more specific version of my question and list what information you would need."
In our project: this is how we turned "solve this" into a prompt that names the language, the input type, and the edge cases.

4. Cognitive verifier pattern

The cognitive verifier pattern asks the model to break a problem into smaller questions, answer them, and then check its own work. It reduces the chance of a confident but wrong answer, because the model has to show its reasoning steps.

Example: "Break this problem into sub-questions, answer each one, then check whether your code handles an empty list."
In our project: the empty-list test case checks whether the verification step actually caught an edge case.

5. Flipped interaction pattern

In the flipped interaction pattern, the model asks you questions instead of answering right away. You give information one piece at a time until the model has enough to help. This is useful when you do not yet know what details matter.

Example: "Ask me one question at a time until you know my language, my skill level, and the input size. Then write the solution."
In our project: we used this to see whether the model would ask about constraints we had not thought to mention.

Limitations

We used one chatbot and five test cases. The comparison is small, so the results should be read as a demonstration, not as proof. Some patterns may work better for other problems or other models.
